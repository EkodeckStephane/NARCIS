# NARCIS — Canonical Final Detector Audit Execution Freeze

This record is committed before inspection of any new detector outcome generated by `tools/tomm_final_detector_audit.py`.

## Purpose

The final multi-session detector threat model in `TOMM_FINAL_DETECTOR_AUDIT_FREEZE.md` is unchanged: five Caltech-101 partitions (`11, 29, 47, 71, 101`), thirty authenticated sessions, image-disjoint 65/35 train/test splits, twenty repetitions per partition, and the frozen SRM-lite/ExtraTrees, GLCM/logistic, and 30-head lightweight CNN detectors.

The purpose of this execution freeze is to remove one infrastructure-dependent source of non-reproducibility discovered during the final claim/code/data audit: image identifiers produced by the historical loader could contain an absolute dataset path, while group-bank cover ranking authenticates identifiers inside its HMAC selection context. The same corpus moved to another machine could therefore produce a different deterministic tie-break ordering despite identical image contents and protocol parameters.

## Canonical identifier rule

For this execution and all artifacts derived from it, every Caltech-101 cover identifier is fixed to:

```text
relative_path_from_dataset_root.as_posix()
```

No category, image content, detector feature, attack outcome, steganalyzer score, payload recovery outcome, or manuscript result is used in this normalization. It only removes the machine-specific absolute path prefix and path-separator convention.

This normalization is frozen before detector outcomes are observed. It does not alter K, projection candidate families, projection ranking, group-bank objective, group size, FEC, mapping, payloads, session sequences, cryptographic keys, attacks, or detector hyperparameters.

## Dataset source and partition

The execution uses the official Caltech-101 distribution from CaltechDATA record `mzrjq-6wc02` / DOI `10.22002/D1.20086`. The extracted category tree must contain 9,144 readable source images. For each frozen seed, the deterministic NumPy permutation allocates 1,500 images to representation training and the next 7,000 disjoint images to the cover index, matching the fresh TOMM campaign.

## Encoder reconstruction

The encoder is retrained for five epochs with the already frozen fresh-campaign configuration:

- input channel fit: 256×256 RGB;
- encoder boundary: 128×128;
- embedding dimension: 64;
- base channels: 16;
- batch size: 16;
- AdamW, learning rate `1e-3`, weight decay `1e-5`;
- five epochs;
- partition seed used for Python, NumPy, PyTorch and `ChannelAugment`.

Each reconstructed checkpoint is hashed and compared with the SHA-256 recorded in `TOMM_FRESH_CAMPAIGN.md`. A hash mismatch is retained in the manifest rather than hidden. Detector results from a mismatching checkpoint are explicitly treated as a new frozen reconstruction run, not falsely represented as byte-identical reuse of the earlier checkpoint.

## Final NARCIS schedule reconstruction

For each partition, the schedule is rebuilt using the final externally frozen protocol:

- K=8 balanced one-dimensional quantile codebook;
- 16 principal directions plus 32 deterministic random directions;
- projection seed `20260828 + partition_seed`;
- twelve calibration attacks only for projection/group-bank construction;
- group size 5 with strict majority;
- group-bank seed `20260830 + partition_seed`;
- 10 restarts and 6,000 swaps per restart;
- Reed–Solomon parity 128 bytes;
- deterministic 8/32/64-byte workload with ten messages per payload size;
- authenticated sequences 0..29;
- balanced cyclic keyed Gray mapping and frozen group-signature scheduler.

The complete transmitted-cover schedule is persisted as `schedule.csv` and the 7000×30 binary session target as `session_target.npy`. These files are mandatory evidence artifacts for future reproducibility.

## Detector execution

For every partition and repetition `r`, split seed is `partition_seed * 10000 + r`, test fraction is 0.35, and the split is image-disjoint across all 30 heads.

The detectors are exactly those in `TOMM_FINAL_DETECTOR_AUDIT_FREEZE.md`:

1. 52-dimensional residual/SRM-lite features + native multi-output ExtraTrees (`300` trees, `sqrt`, balanced classes);
2. five GLCM features + standardized balanced logistic regression per session head (`max_iter=2000`);
3. the existing lightweight selection CNN converted to a 30-logit head, AdamW `1e-3`, weight decay `1e-4`, BCE-with-logits, batch size 32, eight epochs.

AUC is retained per session head and macro-averaged across the thirty heads. No detector outcome may be used to modify NARCIS or any detector setting after this freeze.

## Evidence package

Each partition artifact must contain at minimum:

- checkpoint and recorded SHA comparison;
- projection candidates and selected projection metadata;
- complete session schedule;
- `session_target.npy`;
- SRM-lite and GLCM feature arrays;
- detector repetition table;
- per-head detector table;
- environment versions and GitHub run/commit identifiers;
- SHA-256 hashes of the principal evidence files.

The manuscript may only be rewritten from these frozen outputs after all five partitions complete and the results are consolidated without outcome-dependent filtering.
